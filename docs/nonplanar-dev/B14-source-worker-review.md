# B14 source-only native worker: critical author review

Date: 2026-10-03. ADR-0095. This is a separate author audit; an independent safety
review remains PENDING and is not substituted by test success.

## Ownership and source reconstruction

Reviewed the actual factory/decoder, Job omission registry, private ViewOwner and
GUI start/process/finish paths. Source-only inputs contain no GuardedJobTask and
require the exact captured editor resource. No analysis Print or second Model
clone remains in the host run. Published source omits only the unchanged thirteen
non-slicing keys; the private view fingerprint still covers original settings.
Both protocols recapture exact source config/matrices/mesh bits/annotations before
child Print.apply. The legacy protocol remains additive and independently tested.

The owner has private construction/current state and monotonic attempt; begin
revokes before validation, destructor revokes and completion consumes exactly
once. Only atomic validity crosses threads. Actual current identity plus epoch
protects raw whitespace, signed zero, one-bit settings, mode and edit/undo.
Old/foreign completion cannot invalidate a replacement. Private ownership is a
display constraint, never proof/export authorization.

## Policy, budgets and export

Reviewed source policy checks before apply and actual resolved Print/region checks
after it. Hook values are excluded from refusal diagnostics. Malformed transport
still refuses, units remain unconfirmed until declared and no hook executes.
Capture progress is emitted before version-2 Print.apply; the watchdog observes
only immutable input validity and its owned child handle. Original OS/progress/
report/RSS caps, UNKNOWN and fixed17 checks remain unchanged. Parent capture/file
observation/marshalling/parsing and sampled RSS are explicit residual gaps.

All completions still pass original envelope/report/manifest/source/request/
software/replay checks. No candidate bytes or credentials are displayed. Global
export channels receive no new bypass. Existing OFF/ZAA callers and project/profile
formats retain their contracts. Exact old candidate comparison plus fresh stock
OFF/ZAA comparisons are required in the milestone record.

## Evidence boundaries

The added request fixture is the original native worker request extracted as a
standalone editing input. It is not a changed golden, mesh, margin or positive
expectation. The new Python oracle factors existing framing and final decimal
checks, binds exact editing bytes and separately recorded owner metadata, and
rejects mutations. It cannot independently reconstruct omitted private settings
from a published source and claims no such qualification.

Actual source-only controller/worker positives and retained negative tests cover
this path. GUI runtime evidence, if available, is limited to explicit synthetic
plate/source fixtures. Broader native 3MF, hardware, hard memory/process tree/crash,
full GUI/P2, full cap/contact/seams, all-motion order/geometry, complete software
provenance and independent safety review remain required. No claim of complete B.
