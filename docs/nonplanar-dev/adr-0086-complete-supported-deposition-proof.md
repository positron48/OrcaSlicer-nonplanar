# ADR-0086: one proof for complete supported final-byte deposition

Status: accepted bounded synthetic contract; implementation and local checks pass.
Full B01–B15 and independent safety review remain open.
Scope: compose existing independently reconstructed head/contact and actual
underlying-support proofs for a complete maximal Deposit block. No broader contact
permission, normative change, production format/profile change or export ALLOW.

A component contact PASS alone cannot establish printable deposition. The new
private combined snapshot requires a complete whole-block geometry/contact proof
and complete underlying vertical/normal Nominal gap plus joined Lower-anchor proofs for
every actual forward-collinear run inside that block. All components derive from
one immutable final-byte material owner. Target reconstruction ends at the whole
block boundary; each support proof uses the exact protected prefix before the whole forming
block. Current/future material cannot supply its underlying support. A corner
regression shows why the old per-run first-intersection claim is different: an
earlier part of the same forming road lies in its near ray. The new child proof
therefore carries an explicit forming_block_first scope and is constructible
only inside the combined factory. Standalone support keeps its original pre-run
meaning and null scope. All already formed/current material still participates
in whole-block geometry/contact; this is not a blanket collision exclusion or
an unscoped first-hit claim against forming material.

The requested run list must exactly match independently reconstructed actual
run boundaries, in order, with no missing/duplicate/partial/extra run. Each run
keeps an explicit existing support policy and carrier cross-slope. The joined
material model and original Nominal/Upper/Lower distinctions remain explicit.
No foreign/equal-content certificate is accepted as input. The factory creates
all components itself and owns the copied policies and protected references.

All reconstruction, geometry and support stages consume one cumulative work
and cell budget and absolute root deadline. Nested stages cannot start a fresh
budget or recover observed cancellation/staleness/exception. Source/material/
rate/scene/contact/join/composite freshness applies throughout; each support
policy is checked while active; completed policies remain under the root
freshness guard and all used policies are checked again before
combined publication. Late guards remove both proof and negative witness.
Failure of either obligation leaves no partial combined certificate.

Diagnostic version1 has an exact five-field root registry, six-field joined
model, three-field run request and ten-field support policy. Missing/extra/
duplicate nested keys, booleans for numeric fields and unsupported ownership
claims refuse. The new headless mode is callable, reports separate failure
witnesses and keeps job UNKNOWN/export false. No production project/profile/
job/cache format changes. Existing standalone support reports and contact v1/v2
inputs/proofs retain their previous semantics and bytes.

Independent final-text geometry and complete-run support references check each
component and the combined owner/boundary/partition relations. Positive cases
include real old support, both directions and rotated frames; no-support/future-
only/thin/too-high/too-small-gap and head/static failures remain negative. Native
verification retains the full original candidate, actual journal, errors,
profile and time/work limits. Original contour old-neighbor FAIL stays a FAIL.

macOS local evidence: focus30 cases/2433417 assertions, selected CTest449/449,
original332 and new105 CLI cases, six strict OFF/ZAA pairs. Native complete
four-packet deposition uses48 cells (28 geometry +20 support),637876 API work;
598131 CLI work/0.534 s under the original1s root. The corner expected-red test
and rising-cross-slope missing Lower-anchor refusal are retained. Exact source,
dependency, binary and lossless raw hashes are recorded in the stage manifest.

This is a composed declared synthetic model, not measured head/material/contact
qualification or full cap fill/union-volume/source-to-plan/job publication.
The fixed mandatory registry and guarded export remain blocked until every full
required domain is independently proved. Standard U1 head/.4 nozzle are known;
firmware/material brand do not block software implementation.
