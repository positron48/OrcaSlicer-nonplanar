# B14 captured later controller: critical author review

Date: 2026-10-03. ADR-0097. This is an author audit; independent safety review
remains PENDING. Full B01-B15 is active.

Capture owns the list before callbacks; all six fields and order enter exact
binary64 canonical bytes, editing version2, job/source resource and view/worker
identities. Row count is bounded before copying. JSON version/type/size/depth,
finite/domain coordinates, unsigned pass ordinal and no extra row fields are
checked. Legacy empty requests preserve version1 bytes. No global profile/3MF
migration, public candidate bytes or new progress-stage ordinal is introduced.

The controller invokes the real ordered factory at Material, then prepares
motion from its actual final ledger. Fixed original width and alternating pass
choices, actual prefix support/normal/roof/dose, tighter nested limits and
publication refusal retain ADR-0096's original mathematical contract. Local
paths and connector declarations do not establish complete fill, contact or
head/route clearance. Existing unsupported steep/duplicate requests remain
refusals; no tolerance, loss, margin, cell/depth limit or negative is weakened.

The native factory checks complete body/final material, original hatch owner,
all adjacent retained path owners, requested original pass and exact before/after
journal ranges. Equal-content copies cannot replace private material ownership.
New lineage and manifest versions bind final motion/bytes to the program. A
compiled test-first negative exposed omission of all later paths from a captured
schema2 job; the boundary now requires the complete program. A changed support
plane bit or version1 request cannot authorize that version3 plan. The existing
departure cannot be combined with a later program by supplying two unrelated
proof pointers. This combination remains refused.

The new shallow STL is separate and preserves original source/goldens. Actual
source/body/later prefixes and final-byte movements are checked independently.
The old100 acceleration declaration fails exact final-rate replay;40 explicitly
reduces execution acceleration below Z50 and supplies a positive scenario. No
final-rate limit is relaxed. This observed rounding sensitivity remains a
limitation for future general motion serialization. The test first reported a
SIGSEGV by dereferencing a missing rate result after a real FAIL; that test was
corrected to require the pointer and preserve the real refusal.

Five focused cases include immutable capture/one-bit hashes, transport versions,
malformed/oversized/type requests, invalid order/duplicates/unsupported roof,
root/child budget/packet/cancel/stale/exception refusal between paths, private
owner/request/program omission and actual supervised child/default replay. The
Python oracle checks exact prefix hashes/order/ranges, original width/directions,
source STL identity, transport vectors, final decimal G-code movement/E/ranges,
nonzero later Z and mutations without invoking planner collision functions.
The generic report oracle now verifies the exact existing SKIPPED material/journal
reasons after a rate failure instead of equating those reasons with an empty
unexecuted replay field. Rate/material success and the full17 registry remain
strict. Existing report identity oracles and real OFF/ZAA/CLI must also pass.

Full filled caps, qualified seams/contact/whole head/connector routes/whole-job
geometry/source/transform/import/3MF/software/physical/atomic publication remain
open. Cooperative host callbacks, hard memory/process-tree/crash containment,
current GUI runtime and Linux/Windows qualification remain pending. No positive
simulation snapshot can authorize physical print or guarded export.
