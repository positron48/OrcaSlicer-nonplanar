# B14 native analysis worker: author critical review

This boundary transfers owned host inputs, never a host proof or reusable
candidate. The factory requires a current privately created Analyzing token,
matching original request SourceFile resource and matching six typed policies.
The child independently reconstructs and recaptures original canonical config,
mesh, metadata, matrix/override/annotation values before entering Print.apply.
Native/generic enum identities are retained; unknown native setting keys refuse.
Pinned Print.apply does not copy referenced Model materials before region config;
this worker domain refuses nonempty volume material IDs before execution rather
than changing the shared Print path. Unreferenced material metadata round-trips.
Omitted network/auth/log/timestamp fields follow the existing exact omission
registry, while the host's private original source still owns them.

The supervised child is the exact direct-argv path chosen by trusted host code,
not a command from a profile. Its working files have a private temporary owner
and RAII cleanup. Output is bounded during polling and reading. Exceptions,
cancel/stale callbacks and deadline failures discard display data. Termination
and wait use the same child handle, avoiding process-global SIGCHLD machinery.
All callbacks must remain short and host finalization must run under existing
Print/Model serialization; checking an atomic token alone cannot substitute for
a final actual Print identity check after an unsynchronized direct model edit.

RSS sampling can miss a transient spike; OS peak observation catches it only
if the native child emits a valid response. The 64 KiB allowance covers fixed
format/write syscalls after observation. macOS RLIMIT_AS/RSS does not establish
hard memory containment; a dedicated probe's attempted cap failed with EINVAL.
CPU/file caps and parent wall supervision are separate observations.
A missing live task observation receives at most a 20 ms transition window:
macOS can drop proc_pidinfo before waitpid reports exit. Persistent loss refuses,
and every published result still requires a valid budgeted OS peak report. Callback
blocking and parent-side bounded parsing are not preemptible by this poll.
Neither the worker API nor direct CLI currently supplies a network/filesystem
sandbox. The future GUI launcher still needs policy and runtime packaging.

Response parsing rejects duplicate/deep/unknown envelope fields, mismatched
host/payload/source/request/software identity, missing stage sequence, malformed
peak observations, changed report/manifest hashes, child job/source mismatch,
missing mandatory checks, implemented-only overall PASS and nonfinite/reordered
movement ranges. These are transport consistency checks, not an independent
collision/support/motion qualification. Raw final bytes stay in the private
native backend; the independent Python oracle scans the separate actual native
reference's final decimal bytes and compares all returned movements/ranges.

The host remains Analyzing until its serialized caller stops/finalizes it; a
successful blocked response does not mint a terminal host token. Late results
must be discarded again at GUI adoption. No automatic Verified transition,
export or printer action is added. Full B remains active, fixed17 retains
13 unimplemented UNKNOWN/NOT_RUN checks, and export stays BLOCK. Full cap/later
passes, qualified contact/seams/order, source/software/physical qualification
and publication are still open. This is author review; independent safety
review is pending.
