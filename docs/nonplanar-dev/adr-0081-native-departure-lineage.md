# ADR-0081: bind protected departure to native job and candidate

Status: bounded B13 dependency contract implemented; full B01–B15 remains active.
Scope: JobNative/JobArtifact, diagnostic consumers and Linux identity workflow.
The normative specification, profiles and production project formats are intact.

The previous native capture could bind an exact complete body/cap journal to a
linear candidate, but correctly refused added Travel rows. B09 now produces a
private immutable SimulationCapDepartureSnapshot. Add it as an explicit optional
sixth argument to the existing capture_guarded_native_plan factory, preserving
the old five-argument path and its canonical bytes. Do not admit arbitrary route
edits through a relaxed prefix or same-content comparison.

The departure must own the exact laid FirstCapMaterial assembly used here, with
the same protected cap source, and the candidate motion plan must take its exact
routed SimulationMotionSource owner as input. Complete native body and hatch
ancestry still refer to the current job/attempt. Equal-content alternate material
and recaptured motion owners refuse. Stale, wrong-phase and foreign tasks refuse.
All output rows and context must match the routed source exactly, except reduced
speed/acceleration; geometry, material, poses, IDs, order and count cannot change.

The protected native plan retains the departure owner and its exact canonical
identity: before/laid/routed journal fingerprints, whole captured head/static
scene/coverage, all nine original clearance components, explicit destination/
lift/speed/acceleration, every leg obligation and complete origin map. Use the
existing bounded 4 MiB encoder with exact binary64 bits, string bytes and sorted
keys. Poll while encoding arrays and before/after publication. Copied callers,
latched callback exceptions, rounding, cancellation and absolute deadline rules
of the existing NativeGuard remain in force. This is lineage, not a persisted
clearance certificate or qualification of the job's opaque resource payloads.

The new departure identity has schema 1; native plan schema 2 links its SHA256;
optional departure candidate manifest schema 3 links that native plan. Ordinary
native schema-1 plans/schema-2 manifests and opaque schema-1 manifests keep their
previous bytes and scopes. The independent diagnostic oracle validates complete
canonical edges and reconstructs lift/transfer/descent from the explicit request,
with exact Travel payloads/IDs/origin map and complete previous rows. Rehashed
mutations must refuse. Finite replacement resource geometry supplied by a file
owner is not authenticated; hashes do not establish truth or geometric clearance.

No mandatory domain becomes PASS from this edge. The fixed 17-check registry
retains four declared final-byte identity/rate/material/replay component results
and thirteen UNKNOWN/NOT_RUN full-job domains, including complete_route_order and
source_model_plan_binding. Report admission ends Unknown, export BLOCK. Print
contact, whole cap fill/seam, earlier/prolog/end motions, qualified resources/
software/transforms/delivery and independent final-byte geometry remain required.

An inherited Linux run of 35503607 exposed an unrelated fixed macOS count in the
native report test: its actual journal has 2257 rows instead of 2218. Replace the
literal with exact complete actual-journal size; existing per-event final-byte
pose/dose checks and identity remain strict. Platform-specific diagnostics retain
their observed counts. Add the departure report to the Linux identity-oracle
step without changing limits or test selection. New-source Linux proof is pending.

Focused/final execution of the new fixture retains identical rows/candidate bytes
but different derived body/dependent fingerprints. Both exact owners validate
separately. The cause remains unqualified; diagnostic comparison does not
normalize runtime identity or permit reuse. Full source provenance stays pending.
