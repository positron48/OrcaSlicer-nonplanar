# B13 build input inventory: author safety audit

Scope is the protected compiled inventory and native job resource binding.
This is an author audit; independent review remains pending.

The dangerous failure would be treating a caller's Software JSON or a stale Git
label as qualification of the current executable. The compiled factory accepts
no data arguments, the snapshot's value constructor is private, and CompiledInputs
rejects any supplied Software resource. Declared mode remains explicitly opaque.
The report's mandatory software check remains UNKNOWN/NOT_RUN in both modes.

The generator hashes contents on every build instead of trusting timestamps.
It creates all selected configuration headers from the same observed file hashes,
writes only changed output, and uses CMake dependency ordering before compilation.
Each inventory is compiled into one translation unit. Exact canonical bytes and
digest must agree before the C++ factory can publish its immutable snapshot.
The independent oracle reads checkout files again after the build and verifies
the full sorted list, every digest and the Software row in actual native reports.

The original job capture root owns all requested resource bytes before callbacks;
the protected inventory is added inside that root. Its size contributes to the
existing resource count/byte limits. Cancellation follows factory acquisition;
all previous native freshness and final deadline checks remain. Failed duplicate,
invalid mode, cancellation and stale callbacks cannot restore an earlier task.
No callback can supply another snapshot through this API.

No mandatory registry row, numerical margin, collision/contact exception, native
path, serializer or independent replay algorithm changes. OFF bypass and declared
version-1 identity tests remain. Native report fingerprints intentionally change
because their Software row now binds different actual bytes; final motion bytes
and proof parameters must remain exact.

Remaining risks are explicit: mtime-preserving source edits may leave reused
objects inconsistent with the inventory, concurrent source mutation can race
compilation, and installed dependencies/linkage/runtime resource copies and
per-source effective flags are unqualified. A matching inventory is not sufficient
to mark the software check PASS. Full GUI/publication, Windows/Linux verification
and physical printer qualification remain separate outstanding requirements.

Repeated Make regressions exposed stale objects and stale executable linkage;
both failures are preserved. Explicit CMake object paths and transitive consumer
outputs fix them without relying on subsecond timestamps. Removal is confined to
the physical build tree and rejects external outputs before touching files.
Eight generator tests cover direct/static/transitive/cyclic consumers, untouched
independent targets, UTF-8 chunks and outside-tree refusal. Ninja unchanged builds
preserve the generated inventory and skip recompilation/relinking.

A Declared job can reproduce the same resource content hash without gaining the
protected runtime pointer. Content equality is not factory provenance or a
qualification certificate; no future mandatory checker may infer either from
the resource name/hash. Existing candidate/report factories still bind actual
job owners and all 17 mandatory checks remain unchanged.

Final local checks: source/package and YAML audit pass; focused 10 / 230; CTest
453 / 453; independent inventory, three native dependency bindings and all
existing context/artifact/report oracles pass. Fifty of 51 parent candidate files
are byte-exact; only the report carrying the new software identity changes.
Final 2205-record / 128014-byte candidate remains byte-exact. Six OFF/ZAA pairs
pass the original comparator. Independent safety review and Linux/Windows/full
GUI/physical verification remain pending.
