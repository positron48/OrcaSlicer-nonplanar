# B14: common native analysis execution backend

Complete orchestration previously lived in fixtures. NativeAnalysis now executes
the existing production factories from one explicit, privately owned editing
request: current job capture, native body, affine hatches, first cap, material,
scene/linear motion, serialization, protected native lineage, independent
final-byte replay and blocked report admission. No earlier selection-stage proof
is reused. The current positive case selects a finite native flat-core ROI; this
is not complete cap fill or a ready main CLI/GUI action.

Every reservation/unit/ROI/pass/hatch/contour/fill choice and the six original
typed parameter roles belongs to exact request bytes stored in the actual job.
Callbacks cannot change the captured values. A shared cooperative root deadline
and exception latch cover all ten stages. Existing producer work limits and
one-second capture/binding/admission/replay ceilings remain. Phase transitions
adopt the actual current token; a replacement survives a stale failure. Refusal
returns no completed snapshot or partial candidate. Final admission deliberately
terminates as Unknown/Failed; no callback runs after admission.
