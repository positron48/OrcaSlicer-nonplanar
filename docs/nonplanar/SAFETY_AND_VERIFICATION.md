# Проверки и границы доверия

## Что требуется доказать программно

Для выбранной математической модели, измеренного профиля, численных ошибок и известного состояния преобразований каждое **непрерывное** движение не пересекает запрещённую геометрию; контактная область работает только по согласованной модели осаждения; дорожка имеет допустимую опору, толщину и объём; команды укладываются в пределы машины и прошивки. Эти утверждения условны и не исключают коробление, загрязнение сопла, пропуски шагов или ошибку измерений вне принятых запасов.

## Обязательные семейства проверок

| Семейство | Проверяется | Блокирующий результат |
|---|---|---|
| Input/scene | Units, transforms, конечность, топология, препятствия, supported domain | Некорректность либо неустранимая неизвестность |
| Profile | Наружный торец/голова, диапазон охвата, измерения, допуски | Неполный/неподтверждённый профиль |
| Compatibility | Resolved режим, firmware, настройки, число голов/деталей | Неподдерживаемое сочетание |
| Geometry | Весь sweep головы, включая подъёмы/спуски и соседний материал | Пересечение или недостаточный bound |
| Support/contact | D_lower, первый зазор, шов, действующая контактная модель | Нет доказуемой опоры/слишком широкий exception |
| Deposition | V, E, width/gap, sequential material, конечный след | Двойной объём, пустоты, невалидная толщина |
| Motion | Оси/рабочая область, скорости/ускорения, extrusion firmware limits | Превышение или неопределённая модель |
| G-code replay | Реальные сериализованные команды, модальность, все переезды | Неизвестная команда, sidecar mismatch |
| Integrity | Snapshot, revision, software/profile/file hashes | Любое несовпадение/устаревание |
| Publication | Проверка после всех фильтров, все export routes | Отсутствующий/неполный отчёт |

«Все проверки» означает эти конкретные семейства и согласованную матрицу тестов, а не обещание обнаруживать любое физическое явление. Перечень mandatory checks входит в версию verifier; отчёт, в котором просто нет трудной проверки, не принимается gate.

## Инструмент и контакт

Вне процесса осаждения весь инструмент жёстко запрещён для пересечения. В печатном движении небольшая зона у выходного отверстия может взаимодействовать с опорой и формируемой дорожкой в измеренном диапазоне. Исключение не удаляет из сцены прошлую соседнюю линию, всю нижнюю часть сопла или цилиндр вокруг головы.

Торцевая площадка имеет ненулевой наружный радиус. На локальной плоскости перепад под её краем зависит от полного градиента поверхности, не только от dZ/ds вдоль пути. Тесты должны включать постоянный Z при поперечном наклоне. Простое снижение скорости не устраняет геометрический конфликт.

## Непрерывное движение

Проверка концов, равномерные отсчёты без bound и voxel collision без указанной погрешности не дают PASS. При adaptive subdivision документировать Lipschitz/геометрическую границу между отсчётами или иной консервативный метод. CCD library exhaustion, неподдерживаемая пара или numerical failure дают UNKNOWN. Bound должен включать погрешность представления материала и инструмента.

## Время и материал

Материал добавляется по последовательности, в том числе внутри текущего сегмента. D_upper — наружная оценка для столкновений; D_lower — внутренний гарантируемый объём опоры; D_nominal — форма/объём для контроля заполнения. Гарантия относится к модели, не к физически точно известному отпечатку. В верхней части с разреженным infill нельзя заменять всё тело solid CAD.

Отдельные tests: head-vs-old-material, head-vs-current-bead, head-vs-adjacent-bead, nozzle annulus contact, unsupported travel descent, material that appears only later, retract without deposition, unretract not a phantom bead.

## Независимый G-code verifier

Собственный ограниченный parser, не доверяющий «безопасно» от planner, формирует последовательность машинных состояний из окончательного текста. Проверяются команды, XYZ, E/F, units, limits, применяемые transforms и материал. Sidecar содержит дополнительные семантические данные, но проходит проверку согласованности с фактическим E/геометрией и input snapshot.

Разрешённый dialect в первой реализации: G0/G1, G90, M83, согласованные G4/M400, temperature/fan commands и необходимый ограниченный набор служебных команд. Экспорт не обязан явно повторять неизменный XYZ на каждой строке, но parser обязан правильно восстанавливать модальность. Дуги, смены инструмента, произвольные macros, G92 XYZ, firmware retraction и динамическая смена компенсаций запрещены до отдельной реализации. G92 E допускается только после специального test и документированной модальности; предпочтительно не создавать его внутри job.

Неизвестный PRINT_START/PRINT_END не превращается в игнорируемый комментарий. Доверенная подготовка оператором может быть отдельной фазой: homing, probing, priming и подтверждение known state на пустом столе. Самостоятельно заявлять, что эти движения проверены collision verifier, нельзя. Пределы проверки и начальная позиция указываются в отчёте. Внутри проверяемой части нет скрытых движений Jinja.

Состояние bed mesh/skew/offsets/flow-speed overrides фиксировано и подтверждено. Произвольные live изменения оператором делают отчёт неприменимым. Не отключать bed mesh посреди отпечатка и не повышать защиты Klipper для подавления ошибки (S11/S12/S14).

## Gate и атаки на интеграцию

Состояние Verified привязано к fingerprint и hash bytes, а не к окну/модели с тем же именем. Проверить поздние callbacks, переключение режима, undo/redo, изменение nozzle profile, reload STEP, смену filament, object overrides, восстановление autosave и stale 3MF.

Все направления выдачи проверяют gate; UI-disabled button недостаточна. CLI, cached export и sliced 3MF имеют собственные отрицательные тесты. В P2 нет send-to-printer для нового режима. Произвольная ручная передача файла вне приложения не является контролируемым маршрутом.

## Правильный отказ и полезность

Неподдерживаемая поверхность → понятный reason code и visual witness; выбранный safe_hybrid может вернуть её в planar. strict_nonplanar → ошибка. Не допускать «PASS потому что непланарных дорожек 0» на положительной модели. В отчёте — выбранная и реально обработанная площадь, число крышек, причины исключения и переходные зоны.
