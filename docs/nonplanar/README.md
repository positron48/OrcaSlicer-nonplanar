# Orca Nonplanar Top Lab
## Комплект для разработки экспериментального форка OrcaSlicer

Дата: **27 сентября 2026 года**. База: **OrcaSlicer v2.4.2**, commit `8500fcdccaa10b5099ac20d252af3a7c560046f1`.

Планарное тело печатается штатным движком Orca; доступные верхние участки — новым модулем криволинейных слоёв. В расчёте участвуют конечный торец сопла, вся установленная голова, уже уложенный материал и все переезды. Итоговый G-code для Klipper проходит отдельный повторный разбор.

**Это задание на разработку, а не готовая модифицированная Orca.** В архиве нет реализации слайсера, сборки приложения, выполненной системной тестовой матрицы, квалифицированного профиля реальной головы или готового G-code. Есть полное ТЗ, контракты, план задач, тестовые сценарии, схемы/примеры данных, вспомогательные проверочные скрипты и генерируемые аналитические STL для экспериментов.

### С чего начать

1. Прочитать [START_HERE.md](START_HERE.md), [SPEC.md](SPEC.md) и [AGENTS.md](AGENTS.md).
2. Создать форк/рабочую ветку закреплённой Orca и поместить **весь этот каталог** в `docs/nonplanar/` репозитория. Ничего автоматически не заменять в корневых LICENSE, README или AGENTS upstream.
3. Передать агенту [первое задание](prompts/01_bootstrap.md). Выполнять Gate A из [BACKLOG.md](BACKLOG.md), а не всё ТЗ одним запросом.

### Что не следует перепутать

Штатный **ZAA** — исходный алгоритм для сравнения, а не полноценный новый режим. Обычная Orca при выключенном новом режиме должна остаться обычной Orca. В новом режиме непроверенный результат не экспортируется ни из GUI, ни через CLI, ни через sliced 3MF; автоматическая отправка на принтер не входит в объём.

Все сценарии слайсера в CSV имеют статус `NOT_IMPLEMENTED_NOT_RUN`. Положительный исход в столбце expected означает **требуемое будущее поведение**, а не уже пройденный тест. Аналитические STL не являются обещанием, что любую такую поверхность сможет напечатать конкретная голова.

### Проверка полученного архива

Из корня распакованного каталога:

```sh
python3 scripts/validate_package.py
python3 -m unittest discover -s scripts -p 'test_*.py' -v
```

Скрипты используют стандартную библиотеку Python 3.10+. Первая команда проверяет комплект, а не G-code. Вторая запускает тесты вспомогательных скриптов, а не Orca. Для дополнительной проверки JSON Schema по draft 2020-12 можно установить `jsonschema` и выполнить `python3 scripts/validate_package.py --json-schema`; это необязательная зависимость только проверки документации.

Полный плановый бюджет разработки — ориентировочно **300–600 активных человеческих часов** с AI-агентом; уточняется после Gate A. Это инженерная оценка, не подтверждённая производительность Codex и не обещание сроков. Подробности и границы — SPEC §28.
