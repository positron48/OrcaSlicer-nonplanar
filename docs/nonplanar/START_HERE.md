# Начало работы

## 1. Прочитать правильный набор документов

Нормативный порядок: SPEC → DATA_CONTRACTS / SAFETY_AND_VERIFICATION → COMPATIBILITY / ORCA_INTEGRATION → тесты и backlog. При конфликте не выбирать удобное толкование: зарегистрировать конфликт и принять ADR. Пересмотр требований пользователем выше проектного решения, но не превращается в неявное ослабление проверок.

Комплект размещается **внутри форка Orca**, например в `docs/nonplanar/`. Его корневой AGENTS.md действует как явная инструкция для этой разработки; агенту, работающему с C++ за пределами каталога документов, нужно явно прочитать его. В существующий корневой AGENTS.md репозитория добавить короткую инструкцию читать `docs/nonplanar/AGENTS.md` для задач Nonplanar Top Lab; не стирать имеющиеся правила.

## 2. Создать рабочую ветку на закреплённой базе

Команды ниже клонируют открытый upstream, но **не создают удалённый форк в аккаунте пользователя** и не собирают приложение:

```sh
git clone --branch v2.4.2 --single-branch https://github.com/OrcaSlicer/OrcaSlicer.git OrcaNonplanar
cd OrcaNonplanar
test "$(git rev-parse HEAD)" = "8500fcdccaa10b5099ac20d252af3a7c560046f1"
git switch -c feature/nonplanar-top-lab
```

При несовпадении SHA остановить bootstrap и выяснить причину, а не менять lock под найденную ревизию. Подмодули, зависимости и инструкции сборки читать на этой ревизии. Удалённый репозиторий для публикации настраивает владелец отдельно.

После копирования комплекта в `docs/nonplanar/`:

```sh
python3 docs/nonplanar/scripts/validate_package.py
python3 docs/nonplanar/scripts/audit_orca_checkout.py --repo .
```

Второй скрипт проверяет локальную историю/маркеры исходников. Он не обращается в сеть, не меняет checkout и не утверждает, что Orca собрана. Для shallow-репозитория, в котором нет baseline commit, результат — ошибка с объяснением.

## 3. Выполнить Gate A

Первое задание — `prompts/01_bootstrap.md`. Обязательный результат: собранная закреплённая Orca на доступной целевой платформе; честный статус второй платформы; реальные baseline OFF/ZAA; карта конвейера и численные инварианты; аналитические проверки сопла/коллизии/объёма; исследованный переход от подложки к крышке.

Наличие рабочих окон upstream не закрывает алгоритмы. Наличие новых классов без вызова из конвейера не закрывает интеграцию. Падающая сборка второй платформы не исправляется удалением её CI.

## 4. Затем пройти MVP и завершённый объём

Gate B — одна крышка, измеренный профиль, полный export gate и первые физические результаты. Gate C — STEP, несколько крышек, калибры, UI/3MF, полный регрессионный пакет и физическая повторяемость. В каждой задаче указывать конкретные test IDs из CSV и requirement IDs из JSON.

## 5. Не запускать принтер из агента

Любые реальные испытания выполняет оператор. Неподтверждённый пример головы разрешает просмотр и анализ, но не печать. Независимый verifier и измерения обязательны до первой печати, даже если это маленький эксперимент.
